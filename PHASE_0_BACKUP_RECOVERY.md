# Phase 0 Backup and Recovery

## Scope and prerequisites

Company JSON snapshots are generated by `apps.administration.tasks.serialize_company_backup` and stored under `PRIVATE_BACKUP_ROOT`. The manifest records model counts, excluded models, unresolved models, and restore prerequisites. Sensitive user, session, and secret data is intentionally excluded; global rows such as currencies, exchange rates, permissions, and Celery beat configuration are not tenant snapshot data.

Backups do not replace separate protected backups of uploaded media, deployment configuration, encryption keys, and the PostgreSQL database. `PRIVATE_BACKUP_ROOT` must be persistent private storage outside the web-served media/static roots, with restrictive filesystem and backup-operator access.

## Tenant restore

1. Preserve a separate copy of the current target database and private files.
2. Prepare an isolated database with the matching schema and an existing target company whose UUID equals the backup manifest's `company_id`.
3. Create/recover the referenced users and global rows first. Inspect the manifest's `excluded_models`, `unresolved_models`, and `restore_prerequisites`.
4. Validate without writing:

   ```sh
   python manage.py restore_company_backup /private/path/company.json --company COMPANY_UUID --dry-run
   ```

5. Restore only into the prepared isolated target:

   ```sh
   python manage.py restore_company_backup /private/path/company.json --company COMPANY_UUID
   ```

   The command checks schema version, tenant identity/ownership, references, and existing rows; it restores in one transaction and suppresses signals and side effects. A mismatch or missing reference aborts the restore. It does not restore the Company object or overwrite existing tenant rows.

6. Compare per-model counts with the manifest and verify users, customer/product records, invoices/payments, inventory, journal items, and audit records. Restore media/configuration separately and run representative application tests.

## Operational limits

- A full production PostgreSQL restore and media recovery has not been demonstrated in this pass.
- No RPO/RTO target or measured backup/restore duration is certified.
- Excluded and unresolved models vary by installed model set; read them from each backup manifest instead of assuming a fixed list.
- Never point the restore command at production or use it to overwrite an existing company dataset.
